# 未归类现场（兜底）

确定性规则和页面词表都没给出结论时，交给平台现有的 PhoneAgent（`vision_fallback.recover_with_agent`）。

## 为什么值得兜底

即使判断不了“这是什么”，也多了一次自主尝试的机会；而成功与否**只由业务验收决定**
（`verify()`：现场干净 + 前台回到目标包），绝不用模型自认 finished。

## 动作边界（沿用脚本里的白名单）

允许：Tap / Swipe / Back / Home / Wait。
拦截：Launch App、输入文字、杀进程 —— 这些会改变脚本对业务状态的假设。

## 成功后要沉淀

一次成功的兜底会在 `_draft/` 落一份候选手册（记录特征 + 成功动作）。
在网页「救援技能」里确认后点「提升」，下次同类现场就会被确定性规则直接命中，
不再消耗模型调用 —— 这就是“新脚本需求自己长出来”的路径。

## 调度前先排除“页面正常但业务不动”

前台包名正确、没有弹窗，但脚本的业务动作不生效（最常见：阅读器章末页左滑不翻页），
通用 `verify()` 会直接判“现场已可继续”而不派发任何 handler。
这类现场先按 `reader-stuck.md` 的顺序排查；交给 PhoneAgent 时 goal 要写成可验收的业务目标
（例：把阅读器翻到下一章并保持前台），不要写成“看看哪里不对”。

## 判据

`recover_with_agent` 返回 True 且 `verify()` 通过；任一不满足即判失败，脚本按原逻辑失败退出。
