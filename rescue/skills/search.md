# 停在搜索页 / 搜索结果页

场景：脚本把现场交回时前台还在目标 App 的搜索页或搜索结果页——搜索按钮点了没提交、
结果页分类标签被切到了「社区 / 听书」这类非目标分类，导致脚本一直找不到结果卡。

**不适用**：已经进入正文/播放页、只是翻不动或卡进度 —— 见 `reader-stuck.md`。

## 动作顺序（一次只做一个，做完就取现场比对）

1. 页面上有文字以「原名」开头的行（搜索联想列表；实测有的 App 写作「原名：…」，
   有的写作「原名【…】」）→ 点这一行。
   联想行的标题就是关键词，点它等价于提交搜索；部分机型上点右下角「搜索」经常不生效。
2. 页面上有分类标签（书籍 / 剧集 / 短剧 / 综合）→ 依次点「书籍」「剧集」，最多试 2 个。
   部分 App 关掉广告后常落回结果页且停在「社区」或「听书」标签，那里永远没有书卡。
3. 以上都不成立、但有「搜索」按钮 → 再点一次。
4. 三步都没让页面变化 → 返回失败，下一轮交给 `navigation`（返回键 / 重新拉起）。

## 红线

- 只点无障碍树里有精确文字的控件（`vision_ads.tap_label` 不做模糊匹配），不按坐标乱点。
- 每次动作后必须重新取现场：**标签集合变化或前台 Activity 变化**才算成功。
  播放页/详情页首帧常常还没渲染出可读节点，只比标签会在切换途中误判“没变化”接着多点一下
  （真机实测）。
- 不输入文字、不改关键词——关键词是脚本的业务参数，救援无权改动。
- 最多 2 次标签切换 + 1 次合并搜索提交，避免在结果页来回翻。

## 判据

`capture()` 拿到的 `labels` 集合或 `activity` 与动作前不同，且前台包名仍是目标 App。
