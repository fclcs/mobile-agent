# 手机自动化脚本编写规范

> 本项目所有 ADB 自动化脚本必须遵守的约定。新增脚本或改脚本前先读本文。
> 更新日期：2026-11-20

## 零、最高优先级（每次写/改脚本前必读）

1. **多机型适配是第一要求**：脚本必须能同时跑在 720×1600 与 1080×2400 两种分辨率上。
   禁止写死坐标、固定状态栏高度、只对某个 App 版本有效的控件假设；坐标只能来自运行时
   `bounds`、屏幕比例或截图像素分析，元素优先按语义定位（`text`、短 `resource-id`、
   `content-desc`、`class`）。遇到不同版本 UI 结构不一致时，把两种结构都写进识别逻辑
   （例如同时兼容 Flutter 搜索页与原生搜索页）。
2. **界面认不出时走视觉模型，且全部脚本都要做**：统一复用 `vision_ads.py`，模型名来自网页
   “模型配置 → 视觉模型”（后台注入 `PHONE_AGENT_VISION_MODEL`），脚本不写死模型名。
   dump 读不到或页面持续动画时，先用 `identify_page()` 判断页面类型，再用 `agent_point()` /
   `tap_agent()` 按中文描述定位并点击；不允许按机型分支，也不允许用固定坐标兜底。
3. **业务证据验收**：翻页、集数、转存等必须有真实状态变化证据（业务节点、正文截图摘要），
   命令成功、点击成功、退出码 0 都不算任务成功。
4. **上线流程**：新脚本先在两种分辨率各跑一次短测（5 秒间隔 3–4 页或 1–3 分钟），
   通过后再按真实间隔跑完整时长。

## 一、硬性要求

### 1. 多机型适配：禁止硬编码像素坐标

- 点击/滑动坐标只能在运行时计算，来源限定三种：
  1. `uiautomator dump` 节点上的 `bounds`，取中心点；
  2. `wm size` 读取屏幕宽高后按比例计算（如点中央：`宽/2, 高*0.45`）；
  3. 截图像素分析（正文区域判定、按钮连通域等）。
- 源码里不允许出现 `input tap 78 1120` 这类固定值；日志里打印具体坐标可以，但必须来自当次 dump。
- 元素定位优先用语义属性：`text`、`resource-id`（取 `/` 后的短 id）、`content-desc`、`class`。
  没有语义属性的控件（如部分 App 首页的搜索图标），才用“位置比例 + 尺寸”兜底。
- 至少在两台不同分辨率真机上验证（720×1600 与 1080×2400）。
  记录同一语义控件在两台机器上的坐标差异，证明是运行时算出来的。
- 考虑状态栏、虚拟导航栏、异形屏：用节点位置或比例，不要假设固定状态栏高度。

### 2. 统一使用视觉模型（`vision_ads.py`）

- 视觉识别一律复用项目根目录的 `vision_ads.py`，不要在新脚本里另写模型请求，也不要在脚本里
  写死模型名或密钥。
- 模型来源：网页端“模型配置” → 编辑配置 → **视觉模型（可选）** 字段。任务执行时后端把它注入
  `PHONE_AGENT_VISION_MODEL`，地址和密钥同样来自该条配置（`PHONE_AGENT_BASE_URL` /
  `PHONE_AGENT_API_KEY`），接口 OpenAI 兼容 `/chat/completions`。
- 视觉模型字段留空时自动回退：智谱地址用 `glm-4v-plus`，其他地址用配置里的模型名。
  换视觉模型只需改网页配置并重启任务，不用改脚本。
- 判定输出：A=阅读正文 / B=常规应用界面 / C=广告推广 / D=系统弹窗，只对 **C 且给出边缘关闭控件**
  的结论执行点击；挂机类脚本必须 `confirm=True`（间隔 1.5 秒双帧复核，两次都判 C 才点）。
- 成本与频率控制：单任务 `MAX_CALLS=60`、两次调用最小间隔 2 秒、同截图 90 秒缓存。
  不要在循环里无条件高频调用；模型不可用时安静降级，不阻塞主流程。
- `locate_box()`（视觉问答模型）定位精度不足，只保留给兼容旧逻辑；新代码用手机操作模型
  的千分比坐标定位。
- 所有脚本的自检项：源码中不允许出现绝对像素坐标；不允许按机型分支（`if 机型 == ...`）；
  dump 失败路径的最后手段必须是视觉识别/视觉点击；视觉也不可用时只能明确报错，不能盲点。

### 3. 骨架与工程约定

- ADB 调用统一封装 `adb_bytes`/`adb_text`，所有命令带 `-s DEVICE_ID`；
  设备号来自 `PHONE_AGENT_DEVICE_ID` 或 `DEVICE_SERIAL`，缺失时明确报错。
- 界面读取：`uiautomator dump` 到 `/sdcard/open-autoglm-web-*.xml`，读之前先 `rm`，
  再用 `ElementTree` 解析；兼容 `utf-8` 和 `gb18030`。
- 中文输入：AdbKeyboard（`com.android.adbkeyboard/.AdbIME`）+ `ADB_INPUT_B64`，
  输入后必须校验输入框实际文本。
- 仅使用 Python 标准库（Pillow 可选）；脚本由 Web 后台的 Python 3.11 执行。
- 中文日志，关键步骤可观测；结束打印一行 `*_RESULT=` JSON，进程退出码如实反映成败。
- 绝不打印、保存任何 API Key、FRP Token、网页密码。

### 4. 业务验收，不以“命令成功”代替“任务成功”

- 连接成功、点击成功、截图成功、退出码 0 都不等于业务达成；
  必须有业务证据：页面节点、集数/页码、正文截图哈希变化等。
- 走错页面或证据不足时，如实失败或标记未知，不假报成功。
- 先短测（60–300 秒）通过，再跑完整时长；长任务后台运行 + 轮询日志。

## 二、视频/短剧类 App 的特殊约定

播放中的视频会让 `uiautomator dump` 报 `could not get idle state`：

- 标准流程：尝试 dump → 失败则先做视觉守卫（确认不是广告落地页）→ 点屏幕中央暂停 →
  再 dump → 分析 → `ensure_playing()`（两次截帧摘要相同视为暂停，点中央恢复）。
- 点中央前用 `dumpsys window` 确认当前 activity 仍是播放页；离开播放页时不要盲点中央。
- 集数只认播放页顶部形如 `^第N集$` 的标题节点，不要从整棵 UI 树里抓第一个“第N集”：
  底部选集面板等位置也可能出现类似文字。
- 挂机期间定时探测（如每 5 分钟）读取集数、确认仍在播放；探测时的暂停/恢复要成对出现。

### “每次执行从第 1 集开始”

- 进入播放页后先读当前集数；不是第 1 集时，打开“选集”面板，点第 1 集单元格
  （单元格文字 `1`，短 resource-id），点击后快速暂停并校验顶部标题为第 1 集。
- 校验用快速暂停读取（不要每次读失败都调视觉模型双重确认），避免校验耗时过长，
  视频播完自动跳集导致误判。
- 点的如果正好是当前集，选集面板不会关闭：先确认面板仍在，再按返回键关闭后重试，
  不要在没有确认的情况下直接按返回（会退出播放页）。

## 三、广告与系统弹窗

- 只点击明确的关闭/跳过控件：`关闭/跳过/跳过广告/Close/Skip` 等文字、常见 close 类 resource-id、
  视觉模型确认且落在屏幕边缘的关闭坐标。
- 绝不点击广告内容按钮（立即下载、领取、抽奖、查看详情等）。
- 系统弹窗单独处理（`com.android.systemui`）：低电量省电提示点“不开启”，
  权限弹窗点“取消/拒绝”类按钮；按返回键无效时不要连续按。
- 启动 App 前先唤醒屏幕、收起锁屏和通知栏（`input keyevent 224`、`wm dismiss-keyguard`、
  `cmd statusbar collapse`），否则 `monkey` 可能挂起。

## 四、环境变量约定

| 变量 | 用途 |
|---|---|
| `PHONE_AGENT_DEVICE_ID` / `DEVICE_SERIAL` | 设备 serial |
| `PHONE_AGENT_BASE_URL` / `PHONE_AGENT_API_KEY` / `PHONE_AGENT_MODEL` | 模型配置（后台注入） |
| `PHONE_AGENT_VISION_MODEL` | 网页模型配置的“视觉模型”字段（后台注入），留空回退 `glm-4v-plus` |
| 各脚本自定义（如 `DEMO_SEARCH_KEYWORD`、`DEMO_DURATION_SECONDS`） | 关键词、时长等，便于测试 |

测试运行时脚本所在的 `adb` 目录需要加进 `PATH`。

## 五、验收清单

- [ ] 两台不同分辨率真机跑通导航、输入和核心操作，坐标全部来自运行时计算
- [ ] 视觉模型在广告/遮挡场景生效；长时间挂机无误判误点（证据目录无假阳性截图）
- [ ] 业务证据齐全（集数/页码/正文变化），结果 JSON 与实际状态一致
- [ ] 短测通过后跑完整时长；异常（断网、系统弹窗、息屏）有明确的恢复或失败路径
- [ ] 未在日志、文档中输出任何密钥
- [ ] 手机电量充足并在充电，ADB 在线（`adb devices` 中为 `device`）

## 六、思考/推理模型接入

网页「模型配置」提供 **关闭思考模式** 开关。带思考/推理能力的模型必须打开，否则模型会把
全部输出额度用于 reasoning，正文为空，视觉识别和坐标定位都会失败。

- 请求参数：`enable_thinking: false`（OpenAI 兼容的额外字段）。
  实测：`thinking: false` 会 400；`thinking: {"type":"disabled"}` 反而开启思考。
- 生效范围：`/api/v1/model_configs` 测试连接、工作流与脚本任务注入的
  `PHONE_AGENT_DISABLE_THINKING=1`、`vision_ads.py` 全部请求体、Agent 的 `extra_body`。
- 脚本侧无需改动：`vision_ads` 会自动读取环境变量；新脚本继续只用
  `identify_page` / `tap_agent` / `try_close` 等公共函数即可。
- 另：部分内网/第三方 API 对**图片内容**有安全审核（`sensitive_words_detected`），
  截屏里出现页面文字也可能触发 400。这属于内容策略，不是思考模式问题；
  遇到时应换视觉模型服务，不要反复调整 thinking 参数。
